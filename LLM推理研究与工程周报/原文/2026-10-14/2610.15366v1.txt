Abstract—Design-space exploration of LLM inference clusters
requires predicting how hardware and serving policies interact
with hierarchical key–value (KV) caching. Isolated operation
proﬁles alone do not determine cluster latency: reuse changes com-
putational demand, while KV location, capacity, and contention
govern execution order. We present a compositional discrete-
event simulator based on separating local service costs from
shared resource and KV availability. Compute and transfer models
calibrated on one-preﬁll/one-decode (1P–1D) deployments are
reused across compatible workers, enabling policy and topology
comparisons without per-conﬁguration latency ﬁtting. Validation
against SGLang covers Qwen3-8B and Qwen3-32B on 1P–1D
and 3P–1D clusters. Mean request end-to-end latency error is
1.34% for question answering and 6.36% for captured coding
sessions, measured as mean absolute percentage error. CPU
simulation reduces replay turnaround by 15.33× on average;
real replay includes prescribed arrival gaps. Measured session-
afﬁnity and simulated retention studies demonstrate how the
framework guides policy selection by predicting the joint effects
on computation, latency, and KV occupancy.
Index Terms—LLM inference, performance modeling, hierar-
chical KV cache, discrete-event simulation
I. INTRODUCTION
Designing an LLM inference cluster requires choosing hard-
ware resources and serving policies together. Preﬁll–decode
disaggregation provisions the two phases independently, while
hierarchical key–value (KV) caching and locality-aware routing
reduce repeated computation [1], [2]. Evaluating these choices
on physical deployments is costly, motivating simulation for
early design-space exploration.
Existing inference simulators predict operation costs from
hardware proﬁles and compose them with serving models [3],
[4]. With hierarchical caching, however, operation costs alone
leave a crucial question unresolved: when can a request use
the KV it needs? Routing and retention change both computa-
tional demand and data availability. Evaluating their interaction
requires composing service costs with cache state and resource
dependencies.
The challenge is that a cached preﬁx is not necessarily ready
for computation. Routing determines which worker can access
it, and eviction determines whether it remains available [2], [5].
A host-memory copy requires device capacity and retrieval be-
fore use. Concurrent requests further alter queues and batches.
The simulator must therefore track reusable content, physical
capacity, and execution readiness together.
Our insight is to separate local service costs from the
shared state that determines execution eligibility. We present

II. BACKGROUND AND RELATED WORK
A. Inference with Hierarchical KV Caching
LLM inference comprises preﬁll, which processes uncached
input tokens and produces KV state, and decode, which extends
each sequence token by token. Disaggregation assigns these
phases to separate workers, each using one or more accel-
erators. It allows independent provisioning but requires KV
handoff and sufﬁcient destination capacity [1]. Within a worker,
continuous batching updates the active request set between
iterations [7], while chunked preﬁll divides prompt processing
into smaller steps [8]. Paged allocation and preﬁx caching
further shape execution by managing physical KV capacity and
reusing content across requests [5], [9].
Hierarchical caching extends reuse beyond device memory
by retaining KV in host memory or storage, at the cost of
retrieval [10], [11]. Figure 1 illustrates this organization. Device
memory (L1) supplies computation directly; local host memory
(L2) retains preﬁxes beyond device capacity; and optional
shared or persistent storage (L3) extends retention or access
across workers [2]. We distinguish tiers by accessibility, so
shared DRAM may serve as L3. This distinction separates the
existence of a reusable preﬁx from the cost and feasibility of
accessing it.
B. Related Inference Cluster Simulators
Execution-cost modeling. Vidur uses operator proﬁles [3],
with preﬁx caching and routing policies in its canary imple-
mentation [12]. LLMServingSim combines layerwise proﬁling
with serving and interconnect simulation [4], including P–D
handoff and device/CPU/CXL caching [13]. These approaches
represent hardware and execution in detail. Our whole-iteration
and effective-path calibration instead aligns service estimates
with the target engine’s execution boundaries; explicit KV
dependencies compose them into cluster behavior.
Stateful workload modeling. Frontier uses role-speciﬁc
abstractions for disaggregated execution and stateful re-
quests [14]. AgentServeSim models agent-program orchestra-
tion, including completion-driven successor release and reten-
tion across tool gaps [15]. Such dependencies address how
workload demand evolves. Our open-loop coding replays hold
recorded ordering and scaled interarrival intervals ﬁxed, al-
lowing cluster policies to be evaluated under identical offered
demand.

dependencies separately from policy selection and service pre-

B. User Conﬁguration and Policy Injection
A cluster conﬁguration deﬁnes the available workers, their
execution settings, connectivity, and per-tier capacities. Work-
loads retain token identities for preﬁx matching, output lengths
for generation, and session identiﬁers for afﬁnity routing. Ar-
rivals are independent of simulated completions, so alternative
policies receive the same open-loop demand.
Gateway policies select workers, while KV policies select
reuse and retention actions, including eviction, writeback, and
prefetching. These decisions are proposals subject to the or-
chestrator’s capacity and dependency checks. Separating policy
selection from physical allocation preserves a common model
of feasible execution across policy changes.
C. Hierarchical KV Representation
Logical KV content may have several physical replicas with
different access costs. We represent each replica by its location,
sharing scope, tier, allocation, and access path. Preﬁx matching
identiﬁes the reusable content, while replica state determines
where it can be accessed and whether it can be reclaimed. P–D
handoff creates availability at another worker through a transfer
rather than an instantaneous change of ownership.
The representation also distinguishes allocated space from
usable data. An in-progress copy reserves destination capacity
but becomes available to computation only on completion. Each
physical allocation is counted once even when several requests
reference it. These rules prevent shared preﬁxes from being
charged repeatedly and concurrent transfers from claiming the
same free space.

E. Discrete-Event Orchestration
The orchestrator advances between arrivals, operation com-
pletions, and maintenance events. Each event updates state and
releases any newly available resources before eligible work is
dispatched. Queueing and overlap consequently emerge from
dependencies and resource occupancy rather than a separately
ﬁtted queueing-delay model.
KV movement obeys three invariants: destination capacity
is reserved before dispatch, source replicas remain protected
while in use, and destination replicas become visible only on
completion. Requests that cannot satisfy admission conditions
remain pending; reservations are released if an operation can-
not proceed. These invariants impose consistent capacity and
availability constraints across policies and access paths.
IV. DATA-DRIVEN MODELING
A. Calibration and Composition
The modeling workﬂow turns local measurements into
reusable compute and transfer predictors (Fig. 3). Calibration
on a logical 1P–1D deployment ﬁxes the model, hardware, and
KV layout while varying operation sizes and batches. Proﬁles
record timing boundaries, ﬁtted parameters, and measured
domains to support reuse across compatible workers.
We ﬁrst compose the proﬁles in 1P–1D replay, where request
timing depends on their interaction with queueing and KV state.
Larger nP–mD conﬁgurations instantiate additional worker
queues and capacities while retaining compatible proﬁles and
modeling shared transfer resources. Changing cluster size there-
fore changes resource occupancy and event ordering without
requiring an end-to-end latency ﬁt.
Component tests assess service-time prediction, while clus-
ter tests evaluate how those costs compose under admission,
queueing, and multi-source contention. We use frozen proﬁles

C. Transfer Modeling
Transfer cost depends on the operation, direction, endpoints,
and physical payload. The KV page allocation and worker
execution layout determine how token counts map to bytes.
For operation and path k, we use
btk(B) = αk + hk(B),
(3)
where B is payload size, αk is startup cost, and hk is a linear
or piecewise-interpolated function. Each direction and path
is calibrated separately. The backend combines this isolated
service estimate with sharing rules to determine completion
time; the orchestrator then makes the transferred KV available.
P–D handoff. Calibration measures the interval from preﬁll
completion to handoff completion on the preﬁll host. Because
the interval includes software coordination, its ﬁtted rate rep-
resents effective service rather than NIC bandwidth. In the
evaluated conﬁguration, each source processes one active chunk
at a time in FIFO order. When N chunks transfer concurrently
to a decode worker, each receives 1/N of its isolated size-
dependent rate. Multi-source cluster replay tests this sharing
assumption beyond the pairwise calibration.
Cross-tier movement. Separate host-to-device (H2D) and
device-to-host (D2H) models capture preﬁx retrieval and write-
back. The same interface can represent lower storage tiers
through metadata queries and payload reads or writes: lookup
cost depends on the metadata operation, while payload cost
depends on bytes and access path. The evaluated proﬁles cover
GPU–host movement. Recorded payload ranges distinguish
interpolation from extrapolation.
V. EVALUATION
We test calibration reuse through component and cluster
accuracy, compare against LLMServingSim, and quantify cache
ﬁdelity and evaluation time.
A. Experimental Setup
We evaluate SGLang [5] serving Qwen3-8B and Qwen3-
32B [6] on RDMA-connected NVIDIA L20Z hosts. Comparing
1P–1D and 3P–1D varies preﬁll capacity with one decode
worker. Each worker uses two GPUs with tensor parallelism
(TP2) and 262144 device KV tokens; each P additionally
provides 524352 host-memory tokens through HiCache [11].
Both topologies use round-robin routing, BF16 KV, 64-token
pages, 4096-token preﬁll chunks, and a limit of 32 running
requests per worker. D-side preﬁx and host caching, as well as
L3, are disabled.
The workloads cover document reuse and session reuse
(Table II). QASPER [17] and SQuAD [18] requests share
preﬁxes within a paper or paragraph and generate 128 tokens.
Hashed sampling retains complete document groups to preserve
reuse opportunities. Coding traces [19] (labeled Agentic in
results) retain complete sessions whose lengths fall within the
source dataset’s interquartile range.

D. Comparison with LLMServingSim
We compare against LLMServingSim [4], [13] on the same
workloads with identical tokens, arrivals, routes, and KV ca-
pacities. The baseline uses measured L20Z kernel proﬁles, cal-
ibrated collective and host-transfer rates, and nominal RDMA
bandwidth. We correct veriﬁed host-capacity accounting and
cache-hit handling issues. Its native P–D path aborts on all ten
coding cases; to complete these replays, we add reservation of
decode capacity for the prompt and generation budget before
preﬁll. The compute, batching, and caching models remain
unchanged. This adapted baseline tests the transfer of a vLLM-
based execution model to our SGLang deployments.
Our E2E and TTFT errors are consistently lower (Table IV).
Coding E2E MAPE averages 6.36%, versus 15.21% for the
baseline, and coding TPOT errors are lower in every case. QA
TPOT favors LLMServingSim for 8B and our simulator for
32B.

VI. APPLICATIONS
The calibrated framework supports policy selection by pre-
dicting how reuse changes work, latency, and occupancy. We
evaluate session afﬁnity on real deployments and TTL retention
in simulation, keeping workloads, hardware, and service models
ﬁxed.
A. Session-Afﬁnity Routing
Session afﬁnity preserves each session’s initial worker as-
signment to promote local preﬁx reuse [20]. We assign sessions
cyclically and compare afﬁnity with round-robin routing on the
3P–1D coding traces at 0.5 requests/s for 8B and 0.25 for 32B.
Predictions are frozen before measurement, and each policy is
measured once from empty caches.
The simulator captures the policy’s main effect: lower preﬁll
work with little change in E2E latency. Predicted uncached-

VII. CONCLUSION
We presented a compositional simulator for evaluating LLM
inference clusters with hierarchical KV caching. Explicit KV
availability and resource queues enable local compute and
transfer proﬁles to predict behavior across compatible workers.
Across the evaluated deployments, E2E MAPE averages 1.34%
for QA and 6.36% for coding; real replay takes 15.33× the
CPU evaluation time on average. The framework supports
early design-space exploration by quantifying how routing and
retention policies jointly affect computational demand, request
latency, and KV occupancy.
